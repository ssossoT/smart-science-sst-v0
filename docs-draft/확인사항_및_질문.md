# 확인 질문 및 근거 정리

이용약관·개인정보처리방침 초안을 완성하기 위해 아래 질문에 답해 주세요.
각 질문 아래에는 판단 근거(코드/화면에서 확인한 사실)를 함께 적었습니다.

## A. 운영 주체 정보

**Q1. 실제 운영 학교명·담당 교사명·연락처(이메일 또는 전화)는 무엇인가요?**

- 근거: `js/firebase-service.js:77-78,83`의 기본값은 학교명 `동대문중학교`, 교사명 `성소연`, 연락처는 빈 문자열입니다. 반면 `js/demo-data.js:31`의 초기 시드 값은 `○○중학교`(플레이스홀더)입니다.
- 두 값이 서로 다르고, 실제 설정 화면(`설정 → 학교명·교사명`)에서 언제든 바꿀 수 있는 구조라 코드만으로는 "실제 운영 중인 학교"가 어디인지 확정할 수 없습니다.

**Q2. 이 서비스가 특정 학교(예: 본인 학교) 학생만 대상으로 하는지, 여러 학교/불특정 다수도 이용 가능한지?**

- 근거: README와 화면 문구는 "방과후학교 스마트과학반"을 전제로 하지만, 배포는 Vercel 공개 URL이라 접근 자체는 누구나 가능합니다.

## B. 서비스 성격

**Q3. 이 서비스는 행정업무용(수업 준비·구매·재고 관리)과 학생 수업용(활동 기록·소감문) 중 어느 쪽에 무게를 두나요, 아니면 둘 다 동등하게 다루면 되나요?**

- 근거: 화면 구성상 교사용(`teacher.html`)에 수업계획·구매·재고·포트폴리오, 학생용(`student.html`)에 일정·활동·소감문이 있어 두 성격이 혼재되어 있습니다(README.md:9-14).

**Q4. 만 14세 미만 학생에 대해 실제로 보호자 동의를 받는 절차(가정통신문 등)를 운영 중이거나 운영할 계획인가요?**

- 근거: 코드 전체를 검색한 결과 보호자 동의를 확인·기록하는 로직이 없습니다. 대상이 중학생이라 만 14세 미만 학생이 포함될 가능성이 있습니다.

## C. 데이터 저장 방식 (가장 중요)

**Q5. 지금 배포된 "브라우저 로컬 저장 방식"을 기준으로 약관/방침을 확정해도 될까요, 아니면 원래 설계대로 Firebase 클라우드 저장 방식으로 다시 전환할 계획이 있나요?**

- 근거: `firestore.rules`, `storage.rules`, `api/admin`·`api/auth`는 Firebase Auth/Firestore/Storage 사용을 전제로 작성돼 있습니다. 그러나 실제로 화면에서 쓰이는 `js/firebase-service.js:436-446`은 "학생 계정 관리는 서버 없이 이 브라우저에서 바로 처리한다"는 주석과 함께, `/api/admin/students` 호출을 로컬 함수로 가로채고 그 외 모든 API 호출은 오류를 던지도록 되어 있습니다. 즉 **지금 실제로 배포된 코드는 서버/클라우드를 전혀 쓰지 않습니다.**
- 이 초안은 "현재 배포 코드" 기준으로 작성했습니다. 만약 클라우드 방식으로 되돌릴 계획이라면 방침 전체(제3자 제공, 국외이전, 안전성 확보조치 등)를 다시 써야 합니다.

**Q6. 비밀번호를 평문으로 저장하는 현재 방식을 그대로 문서화해도 되나요, 아니면 게시 전에 암호화 등 보완을 먼저 하실 계획인가요?**

- 근거: `js/firebase-service.js:165-171`(학생 로그인 비교), `:428`(저장) 등에서 비밀번호가 암호화 없이 그대로 저장·비교됩니다. 표준 예시 문서의 "일방향 암호화(해시)로 저장되어 개발자도 알 수 없다"는 문구는 현재 사실과 달라 그대로 쓰지 않았습니다.

**Q7. 학생 활동 사진을 실제로 업로드받고 있나요? 있다면 사진에 학생 얼굴 등이 나오는 경우가 많나요?**

- 근거: `js/firebase-service.js:368-383`에 1.5MB 이하 이미지를 base64로 브라우저에 저장하는 코드가 있습니다. 초상권 관련 안내 문구 필요 여부를 판단하기 위한 질문입니다.

## D. 외부 서비스 연동

**Q8. Gemini(AI 초안 생성)·YouTube 검색 기능을 앞으로 켤 계획이 있나요?**

- 근거: `api/gemini/*`, `api/youtube/search.js` 코드와 이를 호출하는 화면(`js/views/assist.js`, `video-search.js`, `settings.js`)이 남아 있지만, `js/firebase-service.js:441-446`의 `callApi()`가 `/api/admin/students`를 제외한 모든 경로에서 즉시 오류를 반환하도록 되어 있어 **현재는 호출되지 않습니다.**
- 켤 계획이 있다면: 어떤 정보(예: 학생 소감문 원문 vs 요약본, 학생 실명 포함 여부)가 전송되는지 구체적으로 알려주셔야 "제3자 제공/국외이전" 조항을 정확히 쓸 수 있습니다. 현재 초안에는 "비활성 상태"로만 언급해 두었습니다.

## E. 보유기간·삭제

**Q9. 학생 데이터(계정·소감문·사진 등)를 언제까지 보관하다 삭제할 계획인가요? (예: 학년/학기 종료 후 즉시, 1년 후, 삭제 안 함 등)**

- 근거: 코드에 자동 삭제·보관기간 로직이 없습니다(`js/views/students.js:7,161`은 "삭제하지 않고 비활성 처리"라고 명시). 표준 예시 문서의 "학년도 종료 시 익년 2월 말까지 보관, 5일 이내 파기"는 이 앱의 실제 동작과 무관한 예시값이라 그대로 옮기지 않았습니다.

**Q10. 삭제/열람 요청이 오면 실제로 어떻게 처리할 계획인가요? (예: 교사가 브라우저에서 직접 데이터 삭제, 별도 문의 채널 운영 등)**

- 근거: 서비스 내에 정보주체가 직접 삭제를 요청할 수 있는 "회원탈퇴" 같은 기능이 없습니다.
